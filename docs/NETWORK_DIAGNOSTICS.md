# 网络诊断

iHub 的 IP 与网络测速是受信任主窗口里的第一方工具。它不会把任意地址、请求体或测速大小暴露给插件和渲染器；所有网络目标与上限都编译在 Rust 宿主中。

## 地址查询

- 首选本地 IPv4/IPv6 通过 UDP 路由选择读取本机将采用的源地址。这个步骤不发送 UDP 数据包，也不枚举网卡名称、MAC 地址或设备标识。
- 公网 IP 仅在用户点击“查询公网 IP”后访问 `https://speed.cloudflare.com/cdn-cgi/trace`。
- 响应最多读取 8 KiB，只接受有效 IP 与受限的边缘机房、TLS、HTTP token。结果仅保留在当前 React 状态，不写入设置或日志。

## 精简测速

一次明确点击会依次执行：

1. 对 Cloudflare `__down?bytes=0` 执行 6 次空载延迟请求，显示中位延迟和相邻样本平均抖动。
2. 从固定 `__down` 端点下载恰好 10,000,000 字节。
3. 向固定 `__up` 端点上传 5,000,000 个确定字节；请求不包含文件、剪贴板或其他用户内容。

原生层拒绝重定向，连接超时为 5 秒、单请求总超时为 18 秒，同时只允许一个测速任务。测速不会自动开始、后台定时运行或实现任意 URL 测速。

测速结果代表当前设备到 Cloudflare 任播边缘的链路，不能等同于所有网站的体验或运营商合约速率。Cloudflare 官方测速引擎同样使用 `https://speed.cloudflare.com/__down` 与 `https://speed.cloudflare.com/__up`；iHub 采用更小的固定流量方案，避免默认引擎按连接能力逐步扩大到数百 MB。

## 明确未实现为“估算”的项目

丢包测试没有用 HTTP 失败率冒充。Cloudflare 官方引擎的 UDP 丢包测试需要自有 TURN 配置，其公开 TURN 服务已弃用；iHub 在没有受控 TURN 基础设施前不展示伪造的丢包数字。
